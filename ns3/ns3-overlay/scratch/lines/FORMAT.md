# 线路配置格式（三维 JSON）

一个 `.json` 文件描述一次运行（高铁列车、汽车，或走路/跑步的行人；下文统一叫"列车"和"轨道"，对行人就是人和他走的路线），分成两部分：

- **按时间写**：列车怎么跑（车速）、什么时候有突发干扰、什么时候在隧道里。
- **按位置写**：轨道（三维折线）、基站及其辐射范围、固定的干扰源。基站和干扰源有两种定位方式：
  - **相对轨道**：线路里程 + 左/右侧 + 离轨道距离 + 天线高度。这是推荐的方式，和铁路上"K 里程、左侧 50 m"的描述习惯一致。
  - **绝对坐标** `[x, y, z]`：适合离线路较远的站，例如山坡上的基站。

程序沿轨道折线对车速积分，得到列车每个时刻的三维位置，再计算它和各基站、干扰源之间的距离。示例见 `hsr.json`（高铁）、`highway.json`（高速公路）、`walk.json`（城市步行）和 `run.json`（城市跑步）。

写好后先用下面的命令检查并预览（不需要运行 ns-3）：

```bash
python3 scratch/preview-line.py scratch/lines/hsr.json
```

## 约定

- **坐标**：单位米，`[x, y, z]`。x、y 是水平面，z 是高度。
- **单位后缀**：单位写在键名里，`_s` 秒，`_m` 米，`_kmh` km/h，`_deg` 度，`_db` dB，`_dbm` dBm，`_dbi` dBi。
- **注释**：以 `_` 开头的键（如 `"_comment"`）一律被忽略，可以用来写注释。
- **拼写检查**：其余未知字段会报错，避免拼错的字段被悄悄忽略。

## 顶层字段

| 字段 | 必填 | 含义 |
|---|---|---|
| `tech` | 否 | `"4g"`（默认）或 `"5g"` |
| `defaults` | 否 | 默认值，见下 |
| `track` | 否 | 轨道折线；不写时为沿 x 轴的直线 |
| `timeline` | 是 | 按时间段的运行描述 |
| `cells` | 是* | 逐个列出的基站 |
| `cell_grid` | 否* | 沿线按间距批量布置的基站 |
| `interferers` | 否 | 固定干扰源列表 |

\* `cells` 和 `cell_grid` 至少要给出一个基站。

## `defaults`

| 字段 | 默认 | 含义 |
|---|---|---|
| `car_loss_db` | 0 | 车体穿透损耗。行人线路里表示手持终端的人体损耗（约 3 dB），时间段里再用它表示建筑、电梯轿厢等额外损耗。只作用于被测手机，不作用于人群里的其他用户 |
| `edge_rsrp_dbm` | -110 | `soft` 范围在边缘处的信号强度门限，见 `cells` |
| `cell` | | 基站默认值。可写 `cells` 里除位置以外的任何字段（`side`、`offset_m`、`height_m`、`tx_dbm`、`range_mode`、`antenna` 等）；单个基站里写了同名字段，以基站自己的为准 |
| `tunnel_cell_spacing_m` | 500 | 隧道内小区（漏缆分段）的间距。`0` 表示隧道里没有覆盖（例如没有室分的过街地下通道），只能收到洞外的基站 |
| `tunnel_loss_db` | 40 | 隧道内外之间的损耗，在洞口 `tunnel_ramp_m` 内逐渐增大到该值 |
| `tunnel_ramp_m` | 100 | 隧道损耗从洞口起增大到 `tunnel_loss_db` 所用的距离。列车隧道约 100 m；几十米长的地下通道写 10 m 左右 |

## `track`：轨道

```json
"track": { "points": [[0, 0, 0], [6000, 0, 0], [9000, 2000, 10], [12000, 2000, 10]] }
```

- **形状**：一串三维点，相邻两点用直线相连，可以表示拐弯和爬坡（z 变化）。
- **起点**：列车从第一个点出发，沿折线前进。
- **长度要求**：轨道必须比列车实际跑过的距离长，否则报错。

## `timeline`：按时间段

```json
"timeline": {
  "0-10":    { "speed_kmh": [0, 100] },
  "60-80":   { "speed_kmh": 350, "interference_dbm": -85 },
  "80-100":  { "speed_kmh": 350, "tunnel": true },
  "130-150": { "speed_kmh": 0 }
}
```

**时间段的键**：写成 `"起-止"`，单位秒，可以带小数。时间段必须从 0 开始、首尾相接、不重叠；最后一段的结束时刻就是仿真时长。

| 字段 | 必填 | 含义 |
|---|---|---|
| `speed_kmh` | 是 | 一个数表示匀速；`[起, 止]` 表示在这段内线性加速或减速；`0` 表示停车 |
| `interference_dbm` | 否 | 这段时间里的突发干扰：手机在整个下行信道带宽内收到的干扰总功率。不写表示无 |
| `tunnel` | 否 | `true` 表示这段时间列车在隧道里。这段轨道上的基站信号要穿过隧道壁（叠加 `tunnel_loss_db`），并按 `tunnel_cell_spacing_m` 自动沿轨道布置洞内小区 |
| `car_loss_db` | 否 | 只在这段时间覆盖默认的车体损耗（行人：楼间遮挡、进楼、电梯轿厢等，写总损耗，例如 3 dB 人体 + 35 dB 轿厢 = 38） |
| `crowd_ues` | 否 | 密集人群：这段时间里手机周围（这段中点处 2–4 m 内）还有多少个用户在下载。他们接入最近的小区，和手机在同一个调度器里分资源 |
| `crowd_mbps` | 否 | 人群里每个用户的下行负载（恒定速率 UDP），默认 4 Mbit/s；需要同时写 `crowd_ues` |

## `cells`：基站

真实线路上的基站立在铁路旁边，一般离轨道 20–100 m，常见左右交替布置。所以推荐用**相对轨道**的方式写位置：

```json
"cells": [
  { "id": "S", "track_m": 10, "side": "right", "offset_m": 25, "height_m": 30, "range_m": 600 },
  { "id": "E", "track_m": 4800, "offset_m": 60, "range_m": 300, "range_mode": "hard" },
  { "id": "C", "track_m": 3000, "side": "right", "offset_m": 80, "tx_dbm": 43,
    "antenna": { "type": "sector", "azimuth_deg": 0, "tilt_deg": 4,
                 "beamwidth_deg": 65, "gain_dbi": 15 } },
  { "id": "P", "pos": [9800, 2300, 60] }
]
```

| 字段 | 含义 |
|---|---|
| `id` | 名称，用于输出和图上的标注 |
| **定位方式一：相对轨道** | |
| `track_m` | 沿轨道的里程（从起点量起的折线长度）。"线路 10 m 处"就写 `10` |
| `side` | 在列车前进方向的 `"left"`（左侧，默认）或 `"right"`（右侧） |
| `offset_m` | 离轨道中心线的水平距离，默认 50 |
| `height_m` | 天线高出该处轨面的高度，默认 35 |
| **定位方式二：绝对坐标** | |
| `pos` | `[x, y, z]`，z 为天线的绝对高度。与 `track_m` 二选一 |
| **覆盖** | |
| `range_m` | 辐射范围，含义取决于 `range_mode` |
| `range_mode` | `"soft"`（默认）或 `"hard"` |
| `tx_dbm` | 发射功率，默认 46。`soft` 模式下给了 `range_m` 时，发射功率由它反推，`tx_dbm` 被忽略 |
| `antenna` | 天线方向图，默认全向 |

预览脚本会打印每个基站离轨道的实际距离和所在里程（用绝对坐标给出的也会算出来）。

## `cell_grid`：沿线批量布站

```json
"cell_grid": [
  { "from_m": 1200, "to_m": 3600, "spacing_m": 1200, "side": "alternate",
    "offset_m": 40, "range_m": 800, "id_prefix": "A" }
]
```

| 字段 | 含义 |
|---|---|
| `from_m`、`to_m` | 起止里程，默认为 0 到列车跑完的距离 |
| `spacing_m` | 站间距（必填） |
| `side` | `"left"`、`"right"`，或 `"alternate"`（左右交替，从左侧开始） |
| `id_prefix` | 生成的名称前缀，上例生成 A1、A2、A3 |
| 其余 | `offset_m`、`height_m`、`range_m`、`range_mode`、`tx_dbm`、`antenna`，对这一组基站都生效 |

`cell_grid` 可以写多组（例如弯道后加密），也可以和 `cells` 混用。

**辐射范围的两种模式**

- **`soft`（默认，接近真实）**：程序自动反推发射功率，使距基站 `range_m` 处的平均信号强度（已计入车体损耗，不含阴影和快衰落）刚好等于 `edge_rsrp_dbm`。超出范围后信号继续衰减而不是消失，相邻小区自然重叠，切换发生在重叠区里。
- **`hard`（受控实验）**：范围内按正常信道计算；超出 `range_m` 后这个基站的信号完全消失。用来故意制造覆盖空洞：两个硬边界基站的范围球不相交时，列车经过中间就会断网。

不写 `range_m` 时，覆盖范围完全由 `tx_dbm`、天线和信道模型决定。

**`antenna`**

| 字段 | 含义 |
|---|---|
| `type` | `"omni"`（全向）或 `"sector"`（定向扇区） |
| `azimuth_deg` | 主瓣水平方向。0 指向 +x，逆时针为正，90 指向 +y |
| `tilt_deg` | 下倾角，向下为正 |
| `beamwidth_deg` | 3 dB 波束宽度，默认 65 |
| `gain_dbi` | 主瓣增益，默认 15 |

## `interferers`：固定干扰源

```json
"interferers": [
  { "id": "J1", "track_m": 3000, "side": "left", "offset_m": 200, "height_m": 20,
    "range_m": 500, "power_dbm": -80 }
]
```

- **定位**：和基站一样，可以用相对轨道（`track_m` + `side` + `offset_m` + `height_m`，默认 100 m、20 m），也可以用绝对坐标 `pos`。
- **作用范围**：列车在以干扰源为球心、`range_m` 为半径的球内时，手机收到 `power_dbm` 的干扰；离开后干扰消失。
- **叠加**：与 `timeline` 里的突发干扰、其他干扰源同时存在时，按功率相加。
- **影响**：干扰叠加在手机热噪声上，会降低 SINR，但不改变切换判决用的 RSRP。

干扰量级参考（20 MHz、手机噪声系数 9 dB 时，热噪声约 -92 dBm）：

| 干扰功率 | SINR 约下降 |
|---|---|
| -92 dBm | 3 dB |
| -82 dBm | 10 dB |
| -72 dBm | 20 dB |

## 校验

读入时检查以下几项，出错会指出具体的字段：

- **时间段**：必须从 0 开始、连续、不重叠，起点小于终点；车速不为负。
- **轨道**：至少两个点，且长度不短于列车跑过的距离。
- **基站**：合并后至少一个；每个基站的 `pos` 和 `track_m` 必须二选一；`track_m` 必须在轨道长度之内；`hard` 模式必须写 `range_m`。
- **干扰源**：`range_m`、`power_dbm` 必填，位置同样是二选一。
- **字段名**：除以 `_` 开头的键外，未知字段一律报错。

## 输出

**预览（`preview-line.py`，不需要运行 ns-3）**

- 打印时间段表：每段的车速、在轨道上的起止里程、干扰、是否在隧道。
- 打印基站列表：三维坐标、范围、所在里程，以及在轨道左侧还是右侧、离轨道多远。
- 生成示意图 `<名字>-preview.png`，从上到下三部分：
  1. **俯视图**：轨道、隧道和洞内小区、各基站及其范围圈（`hard` 模式的范围圈填色）、扇区方向、干扰源、各时间段边界处的列车位置。
  2. **沿线展开图**：横轴是里程，纵轴是在轨道左（+）右（−）侧的距离。俯视图比例尺太大，看不出几十米的偏移，这一部分专门用来核对每个基站在轨道哪一侧、离多远。
  3. **车速曲线**：标出突发干扰和隧道所在的时间段。
- 生成基站近景图 `<名字>-cells.png`：每个基站一张小图，按真实比例（x、y 等比例），以该基站在轨道上的垂足为中心。图中画出轨道和前进方向箭头、基站的实际位置、从轨道到基站的垂直偏移线（标注"左/右 多少米"）、扇区方向，标题里写里程和天线高度。

**仿真时**

- `-trajectory.data`：每 0.1 s 一行，记录时间、x、y、z、车速、当前干扰功率、是否在隧道、服务小区和 SINR。
- `-line.data`：实际使用的基站（包括洞内小区）、反推出的发射功率和干扰源。
