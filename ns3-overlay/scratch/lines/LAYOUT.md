# 高铁和高速公路沿线基站怎么布，仿真里能调什么

## 一、工程上的布站思路

高铁覆盖一般建**专网**：沿线单独规划一串小区，和周边的公网小区隔离开，避免列车在专网和公网之间来回切换。布站的核心矛盾是：列车很快，每个小区只能服务十几秒，每次切换都要在两个小区的**重叠区**内完成。

| 设计项 | 常见做法 | 为什么 |
|---|---|---|
| 站址位置 | 沿铁路一侧或两侧，紧挨线路 | 链状覆盖，只需要覆盖轨道这一条带 |
| 站轨距（基站离轨道的距离） | 几十米到几百米，不同资料给的范围不同（如有文章给出"最佳间距 100–500 m"） | 太近：列车经过基站时多普勒频偏在极短时间内从 +f 翻到 −f，信号强度也剧烈起伏；太远：信号斜着射入车厢，穿透损耗大，沿线覆盖距离变短 |
| 天线挂高 | 高出轨面至少十几米（有文章给出至少 15 m），朝向车窗 | 保证视距，越过路基、声屏障 |
| 天线方向 | 定向天线，主瓣沿线路向两个方向（背靠背两个扇区），水平波束窄，下倾角小 | 能量集中在轨道方向，覆盖更远 |
| 站间距 | 由链路预算决定：4G 约 1–1.5 km，3.5 GHz 5G 约 0.6–1 km | 小区边缘的信号（已计入车体损耗）要高于门限，如 RSRP ≥ −110 dBm |
| 左右布置 | 同侧布站或"之字形"（左右交替） | 之字形让车厢两侧的手机受到的信号更均匀 |
| 重叠区 | 相邻小区信号都够强的区段，长度要能放下一次完整的切换 | 见下面的估算 |
| 小区合并（超级小区） | 把相邻几个射频拉远单元（RRU）合成一个小区，共用小区号 | 列车在合并区内不用切换，切换次数大幅减少 |
| 隧道 | 用泄漏电缆（漏缆）覆盖，铺在高于轨面约 2.1–2.6 m 的洞壁上，正对车窗 | 宏站信号进不了隧道；洞口要和洞外小区留出重叠 |
| 车体损耗 | 新型车厢约 15–25 dB 甚至更高 | 金属车体、镀膜玻璃 |

**重叠区长度估算**（按 3GPP 切换流程推算，不是来自上面的资料）：一次切换要经过测量滤波、时间触发（TTT）、执行三步，粗算约 0.3–0.5 s。车速 350 km/h ≈ 97 m/s，所以每次切换至少需要 30–50 m 的重叠区。考虑到阴影衰落和信号起伏，工程上会留出数倍余量，再加上双向行车，重叠区通常规划到几百米。

## 一（续）、高速公路

高速公路一般不建专网，由公网宏站沿路覆盖，和高铁相比有几处不同：

| 设计项 | 高速公路 | 和高铁的区别 |
|---|---|---|
| 站址位置 | 沿路一侧或两侧；北京地标要求离国道路边不少于 20 m | 同样是链状覆盖，但站址受征地限制，离路距离差别大（几十米到一两百米） |
| 站间距 | 北京地标《线性区域通信基站基础设施设计规范》为新建站预留 300–800 m 的间距；郊野路段由 4G 1.8 GHz 链路预算决定，可以更稀 | 车体损耗小，同样的发射功率覆盖更远 |
| 车体穿透损耗 | 3GPP TR 38.901：普通玻璃的车辆均值 9 dB（标准差 5 dB），镀膜玻璃 20 dB | 高铁车厢 20–30 dB |
| 车速 | 最高 120 km/h，进城、拥堵时频繁减速和停车 | 高铁 250–350 km/h，速度平稳 |
| 隧道 | 山区隧道用泄漏电缆或 RRU 覆盖；北京地标给出漏缆每 500 m 一个隔断 | 相同 |
| 用户 | 同一小区内有多辆车、普通公网用户 | 高铁专网主要服务列车 |

**仿真里的取值**（`highway.json` 和 `run-sweep.py` 的 `hwy-4g`/`hwy-5g`）：

- 车速：120 km/h；`highway.json` 里还有匝道加速、减速进城、拥堵停车 10 s。
- 车体损耗：9 dB。
- 站间距：
  - 4G 1 km，基站离路 80 m；
  - 5G 500 m；
  - `highway.json` 的郊野路段 1.5 km、离路 120 m，城郊路段 600 m、离路 60 m。
- 快衰落：4G 用 EVA 120 km/h 的衰落轨迹；5G 用 3GPP 信道，多普勒按实际车速计算。

郊野路段 1–1.5 km 的站距是按链路预算推算的，不是来自上面的资料：4G 高铁专网在 24 dB 车体损耗下用 1–1.5 km，汽车的车体损耗小 15 dB，站距可以更大，而且公网郊区宏站本来就比高铁专网稀。

## 二、仿真里可以控制的参数

"位置"一列说明参数写在哪里：**JSON** = 线路文件，**命令行** = 程序参数或 `run-sweep.py` 的 `--set`，**待加** = 还没实现。

### 线路与列车

| 参数 | 含义 | 位置 |
|---|---|---|
| 轨道折线 | 三维坐标点，可以拐弯、爬坡 | JSON `track` |
| 车速剖面 | 每个时间段匀速，或线性加/减速，可停车 | JSON `timeline` |
| 隧道 | 时间段；洞内小区间距；洞壁损耗 | JSON |
| 车体穿透损耗 | 全程统一或按时间段设置 | JSON |

### 基站

| 参数 | 含义 | 位置 |
|---|---|---|
| 位置 | 里程 + 左右 + 站轨距 + 挂高，或绝对坐标 | JSON `cells` / `cell_grid` |
| 站间距、之字形 | 批量布站 | JSON `cell_grid` |
| 发射功率 / 辐射范围 | `tx_dbm`，或 `range_m`（soft：反推功率；hard：边界外信号切断） | JSON |
| 天线 | 全向 / 扇区：方位角、下倾角、波束宽度、增益 | JSON |
| 小区合并（超级小区） | 多个 RRU 共用一个小区 | 待加 |

### 无线信道

| 参数 | 含义 | 位置 |
|---|---|---|
| 制式、频段、带宽 | 4G：EARFCN、RB 数；5G：频率、带宽、子载波间隔、TDD 帧结构 | 命令行（可移入 JSON） |
| 路径损耗模型 | Friis / COST231 / 3GPP RMa（视距或含 LOS/NLOS） | 命令行 |
| 阴影衰落、快衰落 | 4G 用衰落轨迹；5G 用 3GPP 信道，含多普勒 | 命令行 |
| 外部干扰 | 按时间段，或干扰源坐标 + 范围 + 功率 | JSON |

### 切换与无线接入网

| 参数 | 含义 | 位置 |
|---|---|---|
| 切换算法参数 | A3 迟滞、TTT | 命令行 |
| 接口时延 | X2、S1-U | 命令行 |
| RRC | 理想 / 真实（5G 只能用理想） | 命令行 |
| RLC | 模式（UM/AM）、缓冲大小 | 命令行 |
| MAC 调度器 | PF / RR 等 | 命令行 |

### 传输层与实验

| 参数 | 含义 | 位置 |
|---|---|---|
| 拥塞控制算法 | CUBIC、BBRv1/v2/v3、Copa | 命令行 `--cc` / `--ccs` |
| 流数、竞争流 | 同一 UE 上的并发流，或加一条其他算法的流 | 命令行 |
| 服务器时延 | 核心网到服务器的单向时延 | 命令行 |
| TCP 参数 | 最小 RTO、延迟 ACK、初始窗口、重传次数 | 命令行 |
| 重复次数 | 每个配置用不同随机种子跑多次 | `run-sweep.py --runs` |

建议把"无线信道"和"切换"两组也放进 JSON（新增 `radio`、`handover` 两节），这样一个文件就能完整描述一次实验，结果可以直接复现。

## 三、画图

`python3 scratch/preview-line.py <线路>.json` 生成两张图：

- **`<名字>-preview.png`**：
  - 俯视图：真实坐标，标出轨道、隧道、基站及其覆盖范围、干扰源；
  - 沿线展开图：横轴是里程，纵轴是左右偏移，便于看清几十米的偏移；
  - 车速曲线。
- **`<名字>-cells.png`**：每个基站一张真实比例的近景图，画出轨道和前进方向、基站的实际位置、到轨道的垂直偏移线和数值（左/右多少米）、扇区方向、天线高度。
